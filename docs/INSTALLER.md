# Установка DzhiggaTV

`DzhiggaTV-Setup-x64.exe` — автономный установщик для текущего пользователя Windows 11 x64. Внутри находится полный portable-дистрибутив с .NET 10, libmpv и SQLite. Подключение к сети и установка .NET отдельно не требуются.

С 1.2.12 автономный EXE использует сжатие single-file bundle. Установленная программа сохраняет полный набор компонентов и кодеков; её запуск и воспроизведение не требуют распаковки этого bundle.

Последний собранный установщик всегда находится в корне проекта: `DzhiggaTV-Setup-x64.exe`. Оба скрипта сборки установщика автоматически обновляют эту копию после успешной сборки и сверяют SHA-256, включая сборку с нестандартным путём выпуска. Бинарный файл исключён из Git.

Запустите EXE, выберите отдельную папку `DzhiggaTV` и нажмите «Установить». По умолчанию используется `%LOCALAPPDATA%\Programs\DzhiggaTV`. Можно создать ярлык в меню «Пуск» и на рабочем столе. После установки доступна кнопка запуска плеера.

Установщик работает без повышения прав. При выборе защищённой системной папки установка может завершиться отказом доступа: используйте предложенную папку профиля. Неподписанная сборка может вызывать стандартное предупреждение Windows о неизвестном издателе.

## Обновление и удаление

Начиная с 1.0.13 основной способ обновления — через подсвеченный номер версии в плеере. После загрузки и проверки файла установщик получает папку установки и текущий профиль, дожидается закрытия плеера, обновляет приложение и запускает его снова. Дополнительные действия в мастере установки не требуются. Публикация выпусков описана в [UPDATES.md](UPDATES.md).

Для обновления выберите существующую папку, созданную этим установщиком. Предыдущая установка проверяется по служебному манифесту и SHA-256 файлов. Если в папке появились посторонние или изменённые файлы, установщик предложит другую папку, сохранив изменения. Portable-папка без метки установщика не перезаписывается автоматически.

Файлы сначала распаковываются во временную папку рядом с целевой, затем выполняется замена папки. При сбое замены предыдущая папка возвращается на место. После успешного обновления удаляются только подтверждённые файлы предыдущей установки; при невозможности очистки резервная папка остаётся рядом.

Удаление выполняется вручную: закройте плеер, удалите папку установленного приложения и созданные ярлыки. Такая же инструкция сохраняется в `Удаление DzhiggaTV.txt`. Установщик не регистрирует приложение в системном списке удаления и не создаёт отдельный автоматический деинсталлятор.

Личные данные хранятся отдельно в `%LOCALAPPDATA%\DzhiggaTV`: настройки, избранное, плейлисты, соответствия и EPG. Установка, обновление и описанное удаление приложения не удаляют эту папку. Установщик запрещает использовать её как папку установки.

## Сборка из исходников

После создания portable ZIP выполнить из корня проекта:

```powershell
.\scripts\build-managed-installer.ps1
```

Параметры `-PortableArchive <абсолютный ZIP>` и `-OutputPath <абсолютный EXE>` задают другие пути. По умолчанию используются `outputs/DzhiggaTV-portable-win-x64.zip` и `outputs/DzhiggaTV-Setup-x64.exe`. Скрипт использует локальный `work/dotnet/dotnet.exe`, если он есть, иначе установленный .NET SDK. Сборка `win-x64` self-contained/single-file встраивает ZIP как ресурс. Запуск внешнего установщика или Inno Setup не требуется.

## Проверка

`src/DzhiggaTV.Installer/SmokeTests/Installer.SmokeTests.csproj` проверяет установку и обновление во временной папке, сохранность неизвестных/изменённых файлов, запрет выхода из папки через ZIP-пути, ADS, имена устройств, дубликаты, коллизии файла и папки, отмену и запрет папки личных данных.

Для проверки именно встроенного архива без записи ярлыков и реестра:

```powershell
.\outputs\DzhiggaTV-Setup-x64.exe --extract-to C:\scratch\DzhiggaTV --no-shortcuts --report C:\scratch\installer-report.json
```

Конечная папка должна называться `DzhiggaTV`, быть пустой или принадлежать этому установщику. Режим `--extract-to` всегда выполняет только извлечение приложения и запись своего манифеста/инструкции; ярлыки, реестр и личные данные он не меняет. Успех подтверждается кодом завершения 0 и `success: true` в отчёте.
