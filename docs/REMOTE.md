# DzhiggaTV Remote · 2.0

Remote встроен в Windows-приложение. Он предоставляет независимый просмотр IPTV в Safari и отдельный пульт ПК в одной домашней сети. Регистрация, облачный сервер, Node.js на телефоне/компьютере пользователя и отдельная мобильная установка не нужны.

## Первое подключение

1. Установите 2.0.3 и нажмите **Remote в левом меню**. Раздел также доступен через **Настройки → Remote**.
2. Подключите телефон к тому же домашнему роутеру. ПК может быть подключён кабелем.
3. Нажмите **Включить Remote**. Если Windows использует профиль «Публичная», проверьте, что сеть действительно ваша домашняя, и выберите для неё профиль «Частная» в настройках Windows. Приложение не меняет профиль автоматически.
4. Отсканируйте QR-код камерой iPhone. Сверьте шестизначный код и разрешите подключение на компьютере.
5. Выберите канал в режиме **Смотреть здесь**. В 2.0.3 запуск со звуком начинается в момент нажатия, до ожидания ответа сервера. Если браузер всё же запрещает запуск (например, из-за собственных ограничений воспроизведения), остаётся штатная кнопка ▶ и понятная подсказка.

QR-ссылка одноразовая и действует три минуты. Кнопка «Обновить код» отменяет старые ожидающие запросы. Доверенное устройство возвращается по обычному адресу сервера без нового QR в течение 30 дней. Адрес может измениться после смены сети; помогает закрепление адреса ПК в настройках роутера. Копирование ссылки создаёт возможность ручного открытия вместо сканирования. В Safari страницу можно добавить на экран Домой через «Поделиться».

Remote продолжает работать при свёрнутом приложении. Сон/выключение ПК или закрытие DzhiggaTV останавливают сервер. Автозапуск Remote включается отдельно. Доступ устройства отзывается в списке подключений на ПК, всех устройств — отдельной кнопкой.

## Телефон и пульт

- **ТВ**: категории, плейлисты, подборки, сортировка, поиск по каналам и названиям передач; список загружается порциями и виртуализирован. Логотипы берутся из общего кэша по мере появления строк.
- **Избранное**: тот же список и порядок, что на Windows. Долгое нажатие или «…» открывает действия канала и существующие пользовательские подборки.
- **Телепрограмма**: общая EPG.ONE, расписание и полное описание. Передачу можно открыть на телефоне либо включить её канал на компьютере. Кнопки Remote включают текущий прямой эфир; архив Windows остаётся доступен в настольном плеере.
- **Пульт**: переключение каналов и возврат на предыдущий, пауза, громкость/mute, полный экран, доступные аудиодорожки. Мультиэкран использует существующее окно и менеджер: 1–4 позиции, выбор канала в каждой, источника звука и развёрнутого экрана.
- **Настройки**: связь с ПК, ограничения, инструкция для экрана Домой, диагностика и отключение устройства.

Просмотр на телефоне не вызывает команду переключения ПК. Громкость телефона регулируется средствами iPhone. Аудиодорожки и субтитры HLS доступны через штатные средства Safari, когда их предоставляет поток. AirPlay и Picture-in-Picture показываются только при наличии соответствующего API. В альбомной ориентации видео занимает экран со штатным управлением. История последних мобильных каналов хранится отдельно в браузере. WebSocket обновляет состояние пульта; после потери связи устаревшие команды не накапливаются.

Во время просмотра шапка, сведения о передаче и строки списка автоматически становятся компактнее. Поиск остаётся видимым, категории/плейлисты/сортировка раскрываются кнопкой фильтров. Стрелка рядом с названием текущего канала сворачивает только изображение: поток остаётся запущенным, а для выбора каналов появляется больше места. При вводе поиска изображение временно сворачивается, освобождая место для экранной клавиатуры. В горизонтальном положении видео и каналы расположены рядом; полный экран включается отдельной кнопкой.

Для сохранения разрешения Safari на воспроизведение со звуком используется один постоянный `<video>`. До сетевого ожидания пользовательское нажатие запускает короткий локальный H.264/AAC-клип с беззвучной аудиодорожкой (2811 байт), после чего источник заменяется выбранным каналом. Клип не запускается сам при открытии страницы, не включает микрофон и не обращается к внешним серверам. Ручная пауза не сбрасывается обработчиками готовности видео. При остановке или закрытии просмотра ожидающий запуск не может включить канал позднее. Для локального MP4 поддерживаются MIME `video/mp4` и Range/206.

## Видео и ограничения

Основной режим — **локальный HLS-прокси без перекодирования**. Поддерживаются master/media playlist, относительные ссылки, аудио, субтитры, MPEG-TS/fMP4, EXT-X-MAP, AES-128 EXT-X-KEY, Range/206 и проверяемые redirects. Непрерывное видео целиком на диск не сохраняется. DRM, HLS content steering/variables и нестандартные схемы источников отклоняются с объяснением.

Режим **Автоматически** проверяет начало источника: HLS передаёт через прокси; другие HTTP-видеопотоки направляет в FFmpeg, если преобразование разрешено. Для несовместимых HLS в 2.0.2 есть **Включить совместимость iPhone** на первом экране Remote. При ошибке декодирования или неподдерживаемом формате телефон один раз пробует fMP4 с AAC-звуком и копированием видео: исходное разрешение, включая UHD, сохраняется. Например, тестовый поток H.264 3840×2160 со звуком MP2 превращается в H.264 3840×2160/AAC. Это не делает любой кодек видео совместимым с любым iPhone: если ошибка остаётся, доступна отдельная кнопка **Преобразовать видео в H.264**. Сетевые ошибки не запускают кодировщик автоматически.

По умолчанию преобразование отключено. Выберите актуальную сборку `ffmpeg.exe` с libx264/AAC (FFmpeg 8 или новее; проверено с 9.0.2) в дополнительных настройках, затем нажмите **Включить совместимость iPhone**. Также автоматически подставляется модуль `%LOCALAPPDATA%\DzhiggaTV\tools\ffmpeg.exe`, если он установлен отдельно; сам путь не включает преобразование без действия пользователя. FFmpeg не включён в установщик. При уже открытой странице на телефоне после включения обновите её и выберите канал заново.

Ограничения: одна общая задача преобразования звука или видео, до двух потоков кодирования CPU, шесть HLS-сегментов с удалением старых. Полное преобразование видео использует 480/720/1080p без увеличения высоты; копирование видео сохраняет исходное разрешение. FFmpeg получает отдельный временный ключ только для чтения медиаресурсов с этого ПК; постоянный ключ телефона ему не передаётся. Внутренние запросы кодировщика не продлевают жизнь оставленного мобильного просмотра. Остановка просмотра/Remote завершает процесс и удаляет его временные файлы. Полное перекодирование видео может заметно повысить нагрузку на CPU.

**Прямое воспроизведение** требует отдельного разрешения на передачу исходных IPTV-адресов и потока без специальных заголовков. Оно раскрывает URL/токен провайдера доверенному браузеру; такие адреса уже нельзя отозвать средствами локального прокси. Прямой режим предварительно проверяет HLS, однако совместимость кодеков определяет браузер. Рекомендуется прокси.

По умолчанию доступны два мобильных потока, настраивается 1–4. Каждое устройство занимает отдельный слот; вкладки одного устройства управляют его общим мобильным просмотром. Отдельный телефон не меняет канал другого телефона. После закрытия страницы поток отменяется; зависшие сессии просмотра освобождаются через 65 секунд отсутствия активности. Ограничение IPTV-провайдера может быть строже и учитывает также Windows и мультиэкран. Обхода этих ограничений нет.

## Безопасность

Remote выключен по умолчанию. Kestrel слушает только выбранный IPv4-адрес частного LAN-адаптера, без `0.0.0.0`, UPnP, туннелей или настроек роутера. Входящие IP ограничены подсетью этого адаптера. Проверка сетевого профиля повторяется во время работы; при переходе к публичному профилю доступ и потоки останавливаются. Несколько адаптеров и VPN отображаются в списке; приоритет у частной физической сети. Текущая реализация использует IPv4 RFC1918.

Сопряжение требует подтверждения на ПК. HttpOnly/SameSite cookie содержит случайный ключ; на диске сохраняется только его SHA-256, срок и отдельный CSRF-токен. Постоянные ключи не попадают в URL и журналы. Для команд проверяются Origin, JSON Content-Type и CSRF; для WebSocket — cookie и Origin. Host проверяется для защиты от DNS rebinding. Есть ограничения запросов, соединений, устройств и задач преобразования. В каталоге никогда нет приватных адресов источников. Пользовательские ограничения видимости применяются к каталогу, программе, логотипам, управлению и каждому запросу медиаресурса.

Прокси не принимает URL от телефона. Выдаются случайные ссылки, привязанные к устройству, каналу и зависимостям проверенного HLS. Проверки схем/адресов и DNS выполняются также на redirects; соединение привязано к проверенному публичному IP. Приватные, loopback, link-local и служебные адреса источников запрещены. Поэтому IPTV от локального NAS/частного IP в этой версии Remote недоступно. Служебные заголовки источника не передаются произвольным сторонним хостам. Смена канала, отзыв доступа и выключение отменяют старые запросы.

HTTP в домашней сети **не шифрует трафик**. Это не офлайн-PWA; Service Worker и требование установки сертификата отсутствуют. HTTPS можно добавить в точке конфигурации Kestrel с доверенным сертификатом и Secure cookie; самоподписанный сертификат не устанавливается автоматически. Брандмауэр Windows не отключается и правила не расширяются автоматически: если телефон не видит сервер, разрешите DzhiggaTV только для частной сети.

## Диагностика

Кнопка **Проверить подключение** на ПК проверяет профиль адаптера и HTTP-ответ самого сервера. Она не заменяет проверку с телефона. Проверьте:

- одинаковую домашнюю сеть и актуальный адрес ПК;
- изоляцию клиентов гостевого Wi-Fi;
- частный сетевой профиль и разрешение приложения в Windows Firewall;
- VPN/виртуальный адаптер, занятый порт и сон компьютера;
- лимиты провайдера и поддержку кодеков Safari при ошибке видео.

Порт по умолчанию 8765, занятый порт сообщает об ошибке. Выбор другого порта выполняется на ПК. Диагностика показывает активные устройства, количество/режимы потоков и приблизительный исходящий трафик; состояние FFmpeg отмечается отдельно. Логов приватных URL и сторонней телеметрии нет.

## Архитектура и сборка

Исходная архитектура сохранена: WPF/.NET 10, libmpv для Windows, SQLite `SqliteStore`, `UserState` для избранного/подборок и `LogoService`/EPG.ONE. Новый `DzhiggaTV.Remote` содержит Kestrel, реестр устройств, ограничения сетей, HLS-прокси и ограниченный FFmpeg-runner. `DesktopRemoteLibrary` снимает снимки разрешённых данных через WPF Dispatcher; запросы EPG выполняются вне UI-потока. `MainWindow.Remote` вызывает существующие методы плеера и мультиэкрана. React/TypeScript/Vite собирается в ресурсы Remote DLL. В установленном приложении используется включённый self-contained ASP.NET Core runtime.

Для разработки нужен Node.js 24.15+ и .NET 10. `scripts/build-remote.ps1` выполняет `npm ci`, тесты и сборку; `publish.ps1` вызывает его автоматически. `Web/dist` включён в исходники для обычной сборки .NET; перед выпуском он пересобирается из исходников с `package-lock.json`. GitHub workflow подготавливает Node и собирает Remote вместе с установщиком.

Проверки: `tests/DzhiggaTV.Remote.Tests` (HTTP, cookie/CSRF/Origin, HLS, Range, SSRF, revoke, лимиты), `Web/src/remote.test.tsx` (интерфейс, независимые действия, виртуализация, ошибки кодеков без повторного запуска по кругу), `tests/DzhiggaTV.Archive.SmokeTests --remote` (настоящее WPF/SQLite/libmpv и декодирование QR). Дополнительные `--media <fixture> --ffmpeg <exe>` проверяют реальный выход AAC/fMP4 и H.264/AAC; `--uhd` с тестовым H.264 3840×2160/MP2 проверяет сохранение разрешения 4K. Переменная `DZHIGGATV_TEST_FFMPEG` добавляет проверку реальной кнопки совместимости в WPF. Тестовый `--serve` слушает только loopback и показывает синтетический каталог; его автоматическое одобрение устройств существует исключительно в тестовом хосте.

Проверено HLS-видео в настольном браузере и мобильная компоновка. В 2.0.1 дополнительно проверены настоящее окно Remote при ширине 620/760/960 DIP, его кнопки включения/выключения, состояние QR, понятные названия адаптеров и корректное чтение частного профиля Windows; выполнен визуальный осмотр окна. Физического iPhone для проверки не было: Safari, AirPlay, PiP, смену ориентации и ограничения конкретного IPTV-провайдера нужно подтвердить на устройстве. Плеер ПК и мультиэкран проверены интеграционно; отдельный физический 4K/HDR-экран в этой проверке не использовался.

Технические основания: [Kestrel endpoints (.NET 10)](https://learn.microsoft.com/aspnet/core/fundamentals/servers/kestrel/endpoints?view=aspnetcore-10.0), [HLS RFC 8216](https://www.rfc-editor.org/rfc/rfc8216), [видео Safari](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari).
