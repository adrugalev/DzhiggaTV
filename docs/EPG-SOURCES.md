# Проверка EPG.ONE

Проверено 18 октября 2026 года из доступной сети. Публичная страница [EPG.ONE](https://epg.one/) публикует XMLTV, архивы пиконов и инструкции подключения. Программа использует эти источники как каталог метаданных: адреса трансляций из эталонного M3U никогда не сохраняются и не подменяют адреса пользовательского плейлиста.

## HTTPS и переадресации

Все восемь заданных адресов `https://epg.one/...` ответили `302` с переходом на `http://ru.epg.one/...`. Попытки HTTPS непосредственно к `ru.epg.one` для основного XMLTV, прозрачного архива и первого эталонного M3U завершились тайм-аутом через 20 секунд. Поэтому сквозную доступность HTTPS подтвердить не удалось.

Начиная с версии 1.0.1 DzhiggaTV автоматически следует опубликованному HTTP-зеркалу на двух точных доменах `epg.one` и `ru.epg.one` со стандартными портами, без имени/пароля в адресе. Приватный IPTV-плейлист сервису EPG.ONE не передаётся. Для сторонних серверов незащищённые перенаправления по умолчанию запрещены; публичное зеркало не может распространить своё разрешение HTTP на другой домен. В версии 1.0.0 общая блокировка HTTP ошибочно мешала обязательному подключению EPG.ONE.

| Файл | Результат HTTP | Формат / размер |
| --- | --- | --- |
| `epg2.xml.gz` | 200 при полной загрузке; 206 при Range | Gzip, `application/octet-stream`, 40 607 411 байт |
| `epg.xml.gz` | 206 | Gzip, `application/octet-stream`, 40 607 306 байт |

| `epgone_transparent_logo.zip` | 206 | ZIP, `application/zip`, 46 972 632 байта |
| `epgone_dark_logo.zip` | 206 | ZIP, `application/zip`, 100 460 098 байт |

| `edem_epg_ico3.m3u8` | 200 | `application/vnd.apple.mpegurl`, сигнатура gzip на транспортном уровне |

Проверка альтернативных XMLTV и ZIP ограничивалась диапазоном первых 64 байт и заголовками. Архивы пиконов целиком не скачивались, CRC всего архива не проверялась. Сервер игнорировал Range для эталонных M3U и возвращал 200. Первый каталог скачан один раз полностью: 73 207 байт в сжатом виде, 4 161 запись метаданных после распаковки.

## Проверка полного XMLTV

Основной `epg2.xml.gz` скачан один раз полностью и обработан реальным потоковым парсером:

- 3 214 элементов `channel`, 3 205 уникальных ID; повторные ID обновляются в базе.
- 577 664 корректные передачи; 2 записи с некорректными или неполными временными данными пропущены.
- Диапазон проверенного файла: с 10 октября по 25 октября 2026 года.
- Весь набор атомарно сохранён в SQLite; поиск передач и получение текущей / следующей передачи проверены на реальных данных.
- В этом запуске чтение XMLTV заняло 7,36 секунды, полный импорт в SQLite — 41,08 секунды. Размер получившейся базы — около 365 МБ. Эти наблюдения зависят от машины и не являются гарантией производительности.

В реальном файле присутствует объявление внешнего DTD на старом домене. Парсер полностью игнорирует DTD (`DtdProcessing.Ignore`, `XmlResolver = null`), ничего оттуда не скачивает и не раскрывает пользовательские сущности. Сохраняются все `display-name`; даты с числовым смещением преобразуются в `DateTimeOffset`, неизвестные буквенные часовые пояса отклоняются. Для частичных дат недостающие календарные компоненты получают первое значение, недостающее время — 00:00; отсутствие часового пояса означает UTC согласно XMLTV.

Парсер ограничивает распакованный поток 1 ГиБ и отдельное текстовое поле 65 536 символами. Поток связан с токеном отмены, включая чтение через `XmlReader`. Любая ошибка сети, распаковки, XML или отмена до фиксации транзакции сохраняет предыдущую рабочую программу. WAL с отдельными SQLite-кэшами позволяет продолжать чтение прежней программы во время обновления.

## Сопоставление и логотипы

Сопоставление реального пользовательского плейлиста с сохранённым каталогом и эталонными именами дало 3 137 автоматических соответствий, 73 неоднозначных канала и 17 каналов без уверенного соответствия. Неоднозначные случаи остаются для ручного назначения. Обозначения качества нормализуются; временные сдвиги и региональные признаки сохраняются. Ручные решения не переписываются автоматическим обновлением, в том числе при одновременном изменении пользователем.

Реальный прозрачный логотип публичного канала EPG `146` загружен и проверен: PNG, 13 869 байт; повторный запрос вернул тот же дисковый файл. Автоматические тесты отдельно проверяют сохранение кэша между экземплярами сервиса, приоритет пользовательской картинки, ограничения размера, защиту от обхода каталогов в ZIP и сохранение индекса пиконов.

Логотипы загружаются по запросу для видимых строк, максимум четыре параллельные загрузки. Постоянный кэш ограничен 256 МиБ, ошибочные адреса получают часовую паузу, свежие картинки не скачиваются повторно. Порядок источников: пользовательский логотип → исходный M3U → сопоставленный XMLTV → эталонный каталог → локальный архив → текстовое обозначение.

Машиночитаемые результаты доступны в `outputs/epg-verification.json`. Они содержат только сведения о публичном сервисе и агрегированные результаты; приватных URL, токенов и содержимого IPTV-плейлиста в отчёте нет.
